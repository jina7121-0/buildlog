# BuildLog 기능 동작 설명서

## 1. 문서 목적

이 문서는 BuildLog 첫 번째 버전의 각 기능이 어떻게 동작해야 하는지 설명합니다.

어려운 개발 용어보다 사용자가 무엇을 하고, 그 결과 무엇을 보게 되는지를 중심으로 작성했습니다. 기준 문서는 `PRD.md`이며, PRD에서 정하지 않았던 세부사항은 사용자와 합의한 추천안으로 보완했습니다.

## 2. 공통 원칙

- BuildLog는 여러 사용자가 가입해서 사용하는 서비스입니다.
- 공부 기록, 할 일, 오류 기록은 처음 만들 때 비공개가 기본값입니다.
- 비공개 기록은 작성자 본인만 볼 수 있습니다.
- 공개 기록은 로그인한 사용자만 볼 수 있습니다.
- 로그인하지 않은 사람은 공개 기록도 볼 수 없습니다.
- 주요 화면은 컴퓨터와 휴대폰 브라우저에서 모두 사용할 수 있어야 합니다.
- 날짜와 시간은 한국 표준시(`Asia/Seoul`)를 기준으로 저장하고 표시합니다.
- 입력이 잘못되거나 저장에 실패하면 입력 내용을 바로 저장한 것처럼 보여주면 안 됩니다.
- 실패했을 때는 사용자가 무엇을 고쳐야 하는지 알 수 있도록 안내해야 합니다. 안내 문구의 정확한 표현은 화면을 만들 때 정합니다.

## 3. 회원 기능

### 3.1 회원가입

#### 1) 사용자가 입력하거나 누르는 것

사용자는 회원가입 화면에서 다음 내용을 입력합니다.

- 이메일
- 비밀번호
- 닉네임

입력을 마친 뒤 회원가입 버튼을 누릅니다.

닉네임은 다른 사용자와 같을 수 없습니다.

#### 2) 정상 처리 결과

- 입력한 이메일, 비밀번호, 닉네임을 바탕으로 새 계정이 만들어집니다.
- 새 사용자는 가입한 이메일과 비밀번호로 로그인할 수 있습니다.
- 가입이 끝나면 자동으로 로그인되고 내 기록 홈 화면으로 이동합니다.

#### 3) 잘못 입력하거나 실패한 경우

- 이메일, 비밀번호 또는 닉네임을 입력하지 않았다면 가입되지 않고 입력이 필요한 항목을 알려줍니다.
- 이미 사용 중인 닉네임이면 가입되지 않고 다른 닉네임을 입력하도록 알려줍니다.
- 이메일 형식이 아니면 가입되지 않습니다.
- 이미 가입된 이메일로는 새 계정을 만들 수 없습니다.
- 비밀번호는 8자 이상이어야 합니다.
- 가입 처리 중 문제가 생기면 계정이 만들어졌다고 표시하지 않고 실패 사실을 알려줍니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 가입 전 사용자가 회원가입 화면을 사용할 수 있습니다.
- 만들어진 계정으로 로그인한 사용자는 자신의 기록을 관리할 수 있습니다.
- 다른 사용자에게는 닉네임만 표시하며 이메일은 공개하지 않습니다.

#### 5) 확인 방법

- 이메일, 비밀번호, 사용하지 않은 닉네임을 입력하면 계정이 만들어지는지 확인합니다.
- 이미 사용 중인 닉네임으로 가입이 거절되는지 확인합니다.
- 필수 항목을 비운 상태에서 가입되지 않는지 확인합니다.
- 새 계정의 이메일과 비밀번호로 로그인할 수 있는지 확인합니다.

### 3.2 로그인

#### 1) 사용자가 입력하거나 누르는 것

- 가입한 이메일
- 가입한 비밀번호
- 로그인 버튼

#### 2) 정상 처리 결과

- 입력한 정보가 가입 정보와 맞으면 로그인 상태가 됩니다.
- 로그인한 사용자는 자신의 기록을 만들고 관리할 수 있습니다.
- 로그인에 성공하면 내 기록 홈 화면으로 이동합니다.

#### 3) 잘못 입력하거나 실패한 경우

- 이메일이나 비밀번호가 비어 있으면 로그인을 진행하지 않고 입력이 필요하다고 알려줍니다.
- 가입 정보와 맞지 않으면 로그인되지 않고 다시 확인하도록 알려줍니다.
- 로그인 처리 중 문제가 생기면 로그인 상태로 바꾸지 않고 실패 사실을 알려줍니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 로그인한 사용자는 자신의 비공개 기록과 공개 기록을 볼 수 있습니다.
- 로그인한 사용자는 다른 사용자가 공개한 기록을 볼 수 있습니다.
- 로그인하지 않은 사람은 비공개 기록과 공개 기록을 모두 볼 수 없습니다.

#### 5) 확인 방법

- 올바른 이메일과 비밀번호로 로그인되는지 확인합니다.
- 틀린 이메일이나 비밀번호로 로그인되지 않는지 확인합니다.
- 로그인한 사용자에게 자신의 기록이 보이는지 확인합니다.
- 로그인하지 않은 상태에서 공개 기록과 비공개 기록을 볼 수 없는지 확인합니다.

### 3.3 닉네임 변경

#### 1) 사용자가 입력하거나 누르는 것

- 내 기록 홈 화면에서 계정 설정으로 이동합니다.
- 새 닉네임을 입력합니다.
- 변경을 요청하는 버튼을 누릅니다.

계정 설정 화면에서 새 닉네임을 입력하고 `닉네임 변경` 버튼을 누릅니다.

#### 2) 정상 처리 결과

- 사용자의 닉네임이 새 닉네임으로 바뀝니다.
- 닉네임이 보이는 화면에는 변경된 닉네임이 표시됩니다.

#### 3) 잘못 입력하거나 실패한 경우

- 닉네임을 비워두면 변경되지 않고 입력이 필요하다고 알려줍니다.
- 다른 사용자가 이미 쓰고 있는 닉네임이면 변경되지 않습니다.
- 변경 처리에 실패하면 이전 닉네임을 유지하고 실패 사실을 알려줍니다.
- 닉네임은 2~20자로 입력하며 한글, 영문, 숫자, 밑줄만 사용할 수 있습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 로그인한 사용자는 자신의 닉네임만 변경할 수 있습니다.
- 다른 사용자의 닉네임은 변경할 수 없습니다.

#### 5) 확인 방법

- 사용하지 않은 닉네임으로 변경되는지 확인합니다.
- 이미 사용 중인 닉네임으로는 변경되지 않는지 확인합니다.
- 변경 후 닉네임이 표시되는 곳에 새 닉네임이 보이는지 확인합니다.

## 4. 공부 기록

공부 기록은 목록 화면, 작성 화면, 상세 화면을 각각 나누어 구성합니다.

### 4.1 공부 기록 만들기

#### 1) 사용자가 입력하거나 누르는 것

- 제목: 1~100자
- 내용: 1~5,000자
- 공개 여부: 기본값은 비공개이며 사용자가 공개로 바꿀 수 있음
- 기록을 저장하는 버튼

작성 날짜와 시간은 사용자가 입력하지 않으며 기록을 만들 때 자동으로 정해집니다.

#### 2) 정상 처리 결과

- 제목, 내용, 공개 여부, 작성 날짜와 시간이 저장됩니다.
- 저장한 기록은 내 공부 기록 목록에서 볼 수 있습니다.
- 공부 기록 목록에는 최근에 작성한 기록이 먼저 보입니다.
- 저장에 성공하면 방금 저장한 공부 기록의 상세 화면으로 이동합니다.

#### 3) 잘못 입력하거나 실패한 경우

- 제목이 없거나 100자를 넘으면 저장되지 않고 제목 조건을 알려줍니다.
- 내용이 없거나 5,000자를 넘으면 저장되지 않고 내용 조건을 알려줍니다.
- 저장 처리에 실패하면 새 기록이 저장된 것처럼 표시하지 않고 실패 사실을 알려줍니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 비공개 기록은 작성자만 보고 수정하거나 삭제할 수 있습니다.
- 공개 기록은 로그인한 다른 사용자도 볼 수 있습니다.
- 공개 기록도 수정하거나 삭제할 수 있는 사람은 작성자입니다.

#### 5) 확인 방법

- 조건에 맞는 제목과 내용으로 기록이 만들어지는지 확인합니다.
- 공개 여부를 바꾸지 않으면 비공개로 저장되는지 확인합니다.
- 작성 날짜와 시간이 자동으로 저장되는지 확인합니다.
- 제목과 내용의 최소·최대 길이 조건을 벗어나면 저장되지 않는지 확인합니다.
- 새 기록이 목록의 가장 앞쪽에 보이는지 확인합니다.

### 4.2 공부 기록 목록과 자세히 보기

#### 1) 사용자가 입력하거나 누르는 것

- 공부 기록 메뉴를 누릅니다.
- 목록에서 읽고 싶은 기록을 누릅니다.

#### 2) 정상 처리 결과

- 내 공부 기록이 최근 작성 순서로 보입니다.
- 기록을 선택하면 제목, 내용, 공개 여부, 작성 날짜와 시간을 확인할 수 있습니다.
- 상세 화면 위쪽에는 제목과 작성 정보를, 그 아래에는 내용을 표시합니다.

#### 3) 잘못 입력하거나 실패한 경우

- 기록이 없다면 `아직 작성한 공부 기록이 없습니다.`라고 안내합니다.
- 기록을 불러오지 못하면 잘못된 내용을 보여주지 않고 실패 사실을 알려줍니다.
- 볼 권한이 없는 비공개 기록은 보여주지 않습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 내 목록과 내 비공개 기록은 작성자만 볼 수 있습니다.
- 공개한 기록은 로그인한 다른 사용자도 공개 기록 화면에서 볼 수 있습니다.

#### 5) 확인 방법

- 여러 기록을 만든 뒤 최근에 작성한 기록부터 보이는지 확인합니다.
- 목록에서 기록을 선택하면 저장한 제목과 내용이 맞게 보이는지 확인합니다.
- 다른 계정으로 내 비공개 기록을 열 수 없는지 확인합니다.

### 4.3 공부 기록 수정

#### 1) 사용자가 입력하거나 누르는 것

- 자신의 공부 기록에서 수정 기능을 누릅니다.
- 제목, 내용 또는 공개 여부를 바꿉니다.
- 수정 내용을 저장하는 버튼을 누릅니다.

#### 2) 정상 처리 결과

- 바꾼 제목, 내용 또는 공개 여부가 저장됩니다.
- 다시 기록을 열었을 때 수정한 내용이 보입니다.
- 수정 날짜와 시간을 저장하고 상세 화면에 표시합니다.

#### 3) 잘못 입력하거나 실패한 경우

- 제목은 1~100자, 내용은 1~5,000자 조건을 지켜야 합니다.
- 조건에 맞지 않으면 수정 내용이 저장되지 않고 고칠 항목을 알려줍니다.
- 수정 처리에 실패하면 이전에 저장된 내용을 유지하고 실패 사실을 알려줍니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 작성자만 자신의 공부 기록을 수정할 수 있습니다.
- 공개 기록을 보는 다른 사용자는 수정할 수 없습니다.

#### 5) 확인 방법

- 제목과 내용을 바꾼 뒤 다시 열었을 때 변경된 값이 보이는지 확인합니다.
- 공개와 비공개를 바꿀 수 있는지 확인합니다.
- 다른 계정으로 수정할 수 없는지 확인합니다.

### 4.4 공부 기록 삭제

#### 1) 사용자가 입력하거나 누르는 것

- 자신의 공부 기록에서 삭제 기능을 누릅니다.
- 삭제 기능을 누르면 `정말 삭제할까요?`라는 확인창을 보여줍니다.

#### 2) 정상 처리 결과

- 해당 공부 기록이 삭제됩니다.
- 삭제한 기록은 내 목록과 공개 기록 화면에서 더 이상 보이지 않습니다.
- 연결된 댓글과 좋아요는 함께 삭제하며, 신고 내역은 운영자가 확인할 수 있도록 유지합니다.

#### 3) 잘못 입력하거나 실패한 경우

- 삭제 처리에 실패하면 기록을 그대로 유지하고 실패 사실을 알려줍니다.
- 이미 없거나 삭제할 권한이 없는 기록은 삭제되지 않습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 작성자만 자신의 공부 기록을 삭제할 수 있습니다.

#### 5) 확인 방법

- 작성자가 삭제하면 목록과 공개 기록 화면에서 사라지는지 확인합니다.
- 다른 계정으로 삭제할 수 없는지 확인합니다.
- 삭제 실패 시 기록이 그대로 남아 있는지 확인합니다.

## 5. 할 일

할 일은 목록 화면에서 추가, 완료 체크, 수정, 삭제를 모두 처리합니다.

### 5.1 할 일 만들기

#### 1) 사용자가 입력하거나 누르는 것

- 제목: 1~100자
- 공개 여부: 기본값은 비공개이며 공개로 변경 가능
- 할 일을 저장하는 버튼

새 할 일은 항상 미완료로 시작하며, 만들 때 완료 상태를 직접 선택하지 않습니다.

#### 2) 정상 처리 결과

- 제목, 완료 여부, 공개 여부가 저장됩니다.
- 새 할 일은 할 일 목록에 표시되며 저장 후 할 일 목록 화면에 머뭅니다.
- 완료하지 않은 할 일이 먼저 보이고, 같은 상태에서는 최근에 작성한 항목부터 보입니다.

#### 3) 잘못 입력하거나 실패한 경우

- 제목이 없거나 100자를 넘으면 저장되지 않고 제목 조건을 알려줍니다.
- 저장 처리에 실패하면 할 일이 추가된 것처럼 표시하지 않고 실패 사실을 알려줍니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 비공개 할 일은 작성자만 볼 수 있습니다.
- 공개한 할 일은 로그인한 다른 사용자도 볼 수 있습니다.
- 수정, 완료 상태 변경, 삭제는 작성자만 할 수 있습니다.

#### 5) 확인 방법

- 공개 여부를 바꾸지 않으면 비공개로 저장되는지 확인합니다.
- 빈 제목과 100자를 넘는 제목은 저장되지 않는지 확인합니다.
- 미완료 항목이 완료 항목보다 먼저 보이는지 확인합니다.

### 5.2 할 일 완료 여부 바꾸기

#### 1) 사용자가 입력하거나 누르는 것

- 자신의 할 일에서 완료 여부를 바꾸는 항목을 누릅니다.

#### 2) 정상 처리 결과

- 미완료에서 완료로 바꾸면 완료 상태와 완료 날짜·시간이 자동으로 저장됩니다.
- 완료된 항목은 완료한 일 목록에서 볼 수 있습니다.
- 완료한 할 일을 다시 미완료로 바꿀 수 있습니다.
- 완료를 취소하면 기존 완료 날짜와 시간을 지웁니다.

#### 3) 잘못 입력하거나 실패한 경우

- 상태 변경에 실패하면 이전 상태를 유지하고 실패 사실을 알려줍니다.
- 다른 사용자의 할 일은 완료 상태를 바꿀 수 없습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 할 일 작성자만 완료 여부를 바꿀 수 있습니다.
- 공개 할 일을 보는 다른 사용자는 완료 여부를 바꿀 수 없습니다.

#### 5) 확인 방법

- 미완료 할 일을 완료로 바꾸면 완료 상태와 완료 날짜·시간이 저장되는지 확인합니다.
- 완료 항목이 완료한 일 분류에 보이는지 확인합니다.
- 다른 계정으로 완료 여부를 바꿀 수 없는지 확인합니다.

### 5.3 할 일 목록과 상태별 보기

#### 3) 잘못 입력하거나 실패한 경우

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 공개한 할 일은 로그인한 다른 사용자가 공개 기록 화면에서 볼 수 있습니다.

#### 5) 확인 방법

- 미완료와 완료 할 일을 각각 만든 뒤 세 분류에 맞게 보이는지 확인합니다.
- 전체 목록에서 미완료가 먼저 보이는지 확인합니다.
- 같은 상태에서는 최근 작성 항목이 먼저 보이는지 확인합니다.

## 6. 오류 기록

오류 기록은 목록 화면, 작성 화면, 상세 화면을 각각 나누어 구성합니다.

### 6.1 오류 기록 만들기

#### 1) 사용자가 입력하거나 누르는 것

- 오류 제목: 1~100자
- 오류 내용: 1~5,000자
- 해결 방법: 해결 전에는 비워둘 수 있으며, 입력할 때는 1~5,000자
- 해결 여부: 미해결 또는 해결
- 공개 여부: 기본값은 비공개이며 공개로 변경 가능
- 오류 기록을 저장하는 버튼

#### 2) 정상 처리 결과

- 오류 제목, 오류 내용, 해결 방법, 해결 여부, 공개 여부가 저장됩니다.
- 미해결 기록은 해결 방법 없이 저장할 수 있습니다.
- 해결 상태로 저장하려면 해결 방법이 반드시 있어야 합니다.
- 해결 상태로 바꿀 때 해결 날짜와 시간이 자동으로 저장됩니다.
- 오류 기록 목록에는 최근 작성한 기록부터 보입니다.

#### 3) 잘못 입력하거나 실패한 경우

- 오류 제목이 없거나 100자를 넘으면 저장되지 않습니다.
- 오류 내용이 없거나 5,000자를 넘으면 저장되지 않습니다.
- 해결 방법을 입력했지만 5,000자를 넘으면 저장되지 않습니다.
- 해결 방법 없이 해결 상태로 저장하려 하면 저장되지 않고 해결 방법 입력이 필요하다고 알려줍니다.
- 처리에 실패하면 오류 기록이 저장된 것처럼 표시하지 않고 실패 사실을 알려줍니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 비공개 오류 기록은 작성자만 볼 수 있습니다.
- 공개 오류 기록은 로그인한 다른 사용자도 볼 수 있습니다.
- 수정, 해결 상태 변경, 삭제는 작성자만 할 수 있습니다.

#### 5) 확인 방법

- 해결 방법이 없는 미해결 오류가 저장되는지 확인합니다.
- 해결 방법이 없으면 해결 상태로 저장되지 않는지 확인합니다.
- 해결 방법과 함께 해결 상태로 저장하면 해결 날짜와 시간이 자동으로 저장되는지 확인합니다.
- 제목, 오류 내용, 해결 방법의 글자 수 조건이 지켜지는지 확인합니다.

### 6.2 오류 기록 목록과 상태별 보기

#### 1) 사용자가 입력하거나 누르는 것

- 오류 기록 메뉴를 누릅니다.
- `전체`, `미해결`, `해결` 중 하나를 누릅니다.
- 자세히 읽을 기록을 누릅니다.

#### 2) 정상 처리 결과

- `전체`에는 모든 내 오류 기록이 보입니다.
- `미해결`에는 해결하지 않은 기록만 보입니다.
- `해결`에는 해결한 기록만 보입니다.
- 목록은 최근에 작성한 오류 기록부터 보여줍니다.
- 기록을 선택하면 저장한 오류 제목, 오류 내용, 해결 방법, 해결 여부와 공개 여부를 확인할 수 있습니다.

#### 3) 잘못 입력하거나 실패한 경우

- 해당 상태의 기록이 없으면 빈 목록임을 알 수 있어야 합니다.
- 목록이나 기록을 불러오지 못하면 잘못된 내용을 보여주지 않고 실패 사실을 알려줍니다.
- 볼 권한이 없는 비공개 오류 기록은 보여주지 않습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 내 오류 기록 목록과 비공개 기록은 작성자만 볼 수 있습니다.
- 공개한 오류 기록은 로그인한 다른 사용자도 공개 기록 화면에서 볼 수 있습니다.

#### 5) 확인 방법

- 미해결과 해결 기록을 각각 만든 뒤 상태별 목록에 맞게 보이는지 확인합니다.
- 전체 목록이 최근 작성 순서인지 확인합니다.
- 다른 계정으로 비공개 오류 기록을 볼 수 없는지 확인합니다.

### 6.3 오류 기록 수정과 해결 처리

#### 1) 사용자가 입력하거나 누르는 것

- 자신의 오류 기록에서 수정 기능을 누릅니다.
- 오류 제목, 오류 내용, 해결 방법, 해결 여부 또는 공개 여부를 바꿉니다.
- 수정 내용을 저장합니다.

#### 2) 정상 처리 결과

- 조건에 맞게 바꾼 내용이 저장됩니다.
- 미해결에서 해결로 바꿀 때 해결 방법과 해결 날짜·시간이 저장됩니다.
- 해결한 오류를 다시 미해결로 바꿀 수 있습니다. 이때 해결 날짜와 시간은 지우지만 작성한 해결 방법은 유지합니다.

#### 3) 잘못 입력하거나 실패한 경우

- 제목, 오류 내용, 해결 방법의 글자 수 조건을 지키지 않으면 수정되지 않습니다.
- 해결 방법이 없는 상태에서는 해결로 바꿀 수 없습니다.
- 수정 처리에 실패하면 이전 내용을 유지하고 실패 사실을 알려줍니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 작성자만 자신의 오류 기록을 수정하거나 해결 상태를 바꿀 수 있습니다.

#### 5) 확인 방법

- 오류 내용과 해결 방법을 수정한 뒤 다시 열었을 때 변경 내용이 보이는지 확인합니다.
- 해결 방법 없이 해결 상태로 바꿀 수 없는지 확인합니다.
- 해결 처리 시 해결 날짜와 시간이 저장되는지 확인합니다.
- 다른 계정으로 수정할 수 없는지 확인합니다.

### 6.4 오류 기록 삭제

#### 1) 사용자가 입력하거나 누르는 것

#### 3) 잘못 입력하거나 실패한 경우

#### 4) 볼 수 있거나 관리할 수 있는 사람

#### 5) 확인 방법

- 다른 계정으로 삭제할 수 없는지 확인합니다.

## 7. 공개와 비공개

### 7.1 기록 공개하기

#### 1) 사용자가 입력하거나 누르는 것

- 자신의 공부 기록, 할 일 또는 오류 기록에서 공개 여부를 `공개`로 바꿉니다.
- 새 기록을 만들 때 선택하거나 기존 기록을 수정할 때 바꿀 수 있습니다.

#### 2) 정상 처리 결과

- 공개 여부가 저장됩니다.
- 공개된 기록은 로그인한 다른 사용자의 공개 기록 화면에 나타납니다.
- 기록 종류에 따라 검색, 댓글, 좋아요 기능을 사용할 수 있습니다.

#### 3) 잘못 입력하거나 실패한 경우

- 공개 상태 변경에 실패하면 이전 공개 여부를 유지하고 실패 사실을 알려줍니다.
- 다른 사용자의 기록은 공개 상태를 바꿀 수 없습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 작성자만 자신의 기록을 공개로 바꿀 수 있습니다.
- 로그인한 사용자는 공개 기록을 볼 수 있습니다.
- 로그인하지 않은 사람은 공개 기록을 볼 수 없습니다.

#### 5) 확인 방법

- 세 종류의 기록이 처음에는 비공개로 저장되는지 확인합니다.
- 작성자가 공개로 바꾸면 다른 로그인 계정의 공개 기록 화면에 나타나는지 확인합니다.
- 로그인하지 않은 상태에서는 나타나지 않는지 확인합니다.

### 7.2 기록 비공개로 바꾸기

#### 1) 사용자가 입력하거나 누르는 것

- 자신이 공개한 기록의 공개 여부를 `비공개`로 바꿉니다.

#### 2) 정상 처리 결과

- 비공개 상태가 저장됩니다.
- 다른 사용자의 공개 기록 화면과 검색 결과에서 해당 기록이 더 이상 보이지 않습니다.
- 작성자는 자신의 기록 화면에서 계속 볼 수 있습니다.
- 공개 상태에서 작성된 댓글과 좋아요는 삭제하지 않고 보관하지만, 기록이 비공개인 동안 작성자만 확인할 수 있습니다. 신고 내역은 운영자가 계속 확인할 수 있습니다.

#### 3) 잘못 입력하거나 실패한 경우

- 상태 변경에 실패하면 이전 공개 상태를 유지하고 실패 사실을 알려줍니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 작성자만 자신의 기록을 비공개로 바꿀 수 있습니다.
- 비공개로 바뀐 뒤에는 작성자만 기록을 볼 수 있습니다.

#### 5) 확인 방법

- 공개 기록을 비공개로 바꾸면 다른 계정의 공개 목록과 검색에서 사라지는지 확인합니다.
- 작성자 계정에서는 계속 볼 수 있는지 확인합니다.

### 7.3 공개 기록 모아보기와 종류별 보기

#### 1) 사용자가 입력하거나 누르는 것

- 공개 기록 메뉴를 누릅니다.
- 공부 기록, 할 일, 오류 기록 중 원하는 종류를 선택합니다.

#### 2) 정상 처리 결과

- 공개된 공부 기록, 할 일, 오류 기록을 한곳에서 볼 수 있습니다.
- 종류를 선택하면 선택한 종류의 공개 기록만 보입니다.
- 공개 기록은 최근에 작성된 기록부터 보여줍니다.

#### 3) 잘못 입력하거나 실패한 경우

- 공개 기록이 없으면 빈 목록임을 알 수 있어야 합니다.
- 불러오기에 실패하면 잘못된 목록을 보여주지 않고 실패 사실을 알려줍니다.
- 로그인하지 않은 사용자는 공개 기록을 볼 수 없습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 로그인한 모든 사용자가 공개 기록을 볼 수 있습니다.
- 기록의 수정과 삭제는 작성자만 할 수 있습니다.

#### 5) 확인 방법

- 세 종류의 공개 기록이 공개 기록 화면에 나타나는지 확인합니다.
- 종류별로 선택했을 때 해당 종류만 보이는지 확인합니다.
- 비공개 기록이 섞여 나오지 않는지 확인합니다.
- 로그인하지 않은 상태에서 공개 기록을 볼 수 없는지 확인합니다.

## 8. 검색

### 8.1 내 공부 기록 검색

#### 1) 사용자가 입력하거나 누르는 것

- 내 공부 기록 화면에서 검색어를 입력합니다.
- 검색을 실행합니다.

#### 2) 정상 처리 결과

- 내 공부 기록의 제목과 내용에서 검색어에 맞는 기록을 보여줍니다.
- 결과를 누르면 해당 공부 기록을 읽을 수 있습니다.

#### 3) 잘못 입력하거나 실패한 경우

- 검색 결과가 없으면 결과가 없음을 알려줍니다.
- 검색 처리에 실패하면 실패 사실을 알려줍니다.
- 검색어가 비어 있으면 현재 목록 전체를 보여줍니다.
- 검색어가 제목이나 내용의 일부와 일치해도 결과에 포함하며 영문 대소문자는 구분하지 않습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 로그인한 사용자는 자신의 공부 기록만 검색할 수 있습니다.
- 다른 사용자의 비공개 공부 기록은 검색 결과에 나오지 않습니다.

#### 5) 확인 방법

- 제목에만 있는 단어와 내용에만 있는 단어가 각각 검색되는지 확인합니다.
- 다른 사용자의 비공개 기록이 결과에 나오지 않는지 확인합니다.
- 일치하는 기록이 없을 때 안내가 보이는지 확인합니다.

### 8.2 내 오류 기록 검색

#### 1) 사용자가 입력하거나 누르는 것

- 내 오류 기록 화면에서 검색어를 입력합니다.
- 검색을 실행합니다.

#### 2) 정상 처리 결과

- 내 오류 기록의 제목과 오류 내용에서 검색어에 맞는 기록을 보여줍니다.
- 해결 방법도 검색 대상에 포함합니다.

#### 3) 잘못 입력하거나 실패한 경우

- 검색 결과가 없으면 결과가 없음을 알려줍니다.
- 검색 처리에 실패하면 실패 사실을 알려줍니다.
- 검색어가 비어 있으면 현재 목록 전체를 보여줍니다. 일부 글자가 일치해도 검색하며 영문 대소문자는 구분하지 않습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 로그인한 사용자는 자신의 오류 기록만 검색할 수 있습니다.
- 다른 사용자의 비공개 오류 기록은 결과에 나오지 않습니다.

#### 5) 확인 방법

- 오류 제목에만 있는 단어와 오류 내용에만 있는 단어가 각각 검색되는지 확인합니다.
- 다른 사용자의 비공개 오류 기록이 결과에 나오지 않는지 확인합니다.

### 8.3 공개 기록 검색

#### 1) 사용자가 입력하거나 누르는 것

- 공개 기록 화면에서 검색어를 입력합니다.
- 필요하면 공부 기록, 할 일, 오류 기록 중 종류를 선택합니다.
- 검색을 실행합니다.

#### 2) 정상 처리 결과

- 공개된 공부 기록, 할 일, 오류 기록 중 검색어에 맞는 기록을 보여줍니다.
- 검색 결과를 누르면 공개 기록을 읽을 수 있습니다.
- 공부 기록은 제목과 내용, 할 일은 제목, 오류 기록은 오류 제목·오류 내용·해결 방법에서 검색합니다.

#### 3) 잘못 입력하거나 실패한 경우

- 검색 결과가 없으면 결과가 없음을 알려줍니다.
- 검색 처리에 실패하면 실패 사실을 알려줍니다.
- 검색어가 비어 있으면 현재 공개 목록 전체를 보여줍니다. 일부 글자가 일치해도 검색하며 영문 대소문자는 구분하지 않습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 로그인한 사용자만 공개 기록을 검색할 수 있습니다.
- 비공개 기록은 검색 결과에 나오지 않습니다.
- 내 할 일을 검색하는 기능은 첫 버전에 포함하지 않습니다.

#### 5) 확인 방법

- 공개된 세 종류의 기록이 검색되는지 확인합니다.
- 비공개 기록은 검색되지 않는지 확인합니다.
- 종류를 선택했을 때 다른 종류의 기록이 결과에 섞이지 않는지 확인합니다.
- 로그인하지 않은 상태에서는 검색할 수 없는지 확인합니다.

## 9. 댓글

댓글은 공개된 공부 기록과 공개된 오류 기록에서만 사용합니다. 공개된 할 일에는 댓글을 제공하지 않습니다.

### 9.1 댓글 작성

#### 1) 사용자가 입력하거나 누르는 것

- 공개된 공부 기록 또는 오류 기록을 엽니다.
- 1~500자의 댓글을 입력합니다.
- 댓글 작성 버튼을 누릅니다.

#### 2) 정상 처리 결과

- 댓글 내용과 작성자가 해당 공개 기록에 연결되어 저장됩니다.
- 저장된 댓글이 공개 기록에 표시됩니다.
- 댓글 작성 날짜와 시간을 저장하고 보여줍니다.

#### 3) 잘못 입력하거나 실패한 경우

- 댓글이 비어 있거나 500자를 넘으면 저장되지 않고 글자 수 조건을 알려줍니다.
- 비공개 기록이나 공개된 할 일에는 댓글을 작성할 수 없습니다.
- 작성 처리에 실패하면 댓글이 등록된 것처럼 표시하지 않고 실패 사실을 알려줍니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 로그인한 사용자가 공개된 공부 기록과 오류 기록에 댓글을 작성할 수 있습니다.
- 로그인하지 않은 사람은 공개 기록을 볼 수 없으므로 댓글도 작성할 수 없습니다.
- 댓글을 볼 수 있는 사람은 해당 공개 기록을 볼 수 있는 로그인 사용자입니다.

#### 5) 확인 방법

- 공개 공부 기록과 공개 오류 기록에 1~500자 댓글이 등록되는지 확인합니다.
- 공개 할 일에는 댓글 기능이 없는지 확인합니다.
- 빈 댓글과 500자를 넘는 댓글이 등록되지 않는지 확인합니다.
- 비공개로 바뀐 기록에 새 댓글을 작성할 수 없는지 확인합니다.

### 9.2 댓글 수정

#### 1) 사용자가 입력하거나 누르는 것

- 자신이 작성한 댓글에서 수정 기능을 누릅니다.
- 댓글 내용을 1~500자로 바꿉니다.
- 수정 내용을 저장합니다.

#### 2) 정상 처리 결과

- 댓글 내용이 변경되어 표시됩니다.
- 댓글을 수정하면 `수정됨`이라고 표시합니다.

#### 3) 잘못 입력하거나 실패한 경우

- 빈 댓글이나 500자를 넘는 내용으로는 수정할 수 없습니다.
- 수정에 실패하면 이전 댓글 내용을 유지하고 실패 사실을 알려줍니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 댓글 작성자만 자신의 댓글을 수정할 수 있습니다.
- 기록 작성자는 다른 사용자의 댓글을 수정할 수 없습니다.

#### 5) 확인 방법

- 댓글 작성자가 내용을 수정할 수 있는지 확인합니다.
- 다른 계정으로 댓글을 수정할 수 없는지 확인합니다.
- 조건에 맞지 않는 내용으로 수정되지 않는지 확인합니다.

### 9.3 댓글 삭제

#### 1) 사용자가 입력하거나 누르는 것

- 댓글에서 삭제 기능을 누릅니다.
- 삭제 기능을 누르면 `정말 삭제할까요?`라는 확인창을 보여줍니다.

#### 2) 정상 처리 결과

- 해당 댓글이 삭제되어 공개 기록에서 더 이상 보이지 않습니다.
- 댓글이 삭제되어도 관련 신고 내역은 운영자가 확인할 수 있도록 유지합니다.

#### 3) 잘못 입력하거나 실패한 경우

- 삭제에 실패하면 댓글을 유지하고 실패 사실을 알려줍니다.
- 삭제할 권한이 없는 사용자는 댓글을 삭제할 수 없습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 댓글 작성자는 자신의 댓글을 삭제할 수 있습니다.
- 공개 기록 작성자는 자신의 기록에 달린 댓글을 삭제할 수 있습니다.
- 그 외 사용자는 댓글을 삭제할 수 없습니다.

#### 5) 확인 방법

- 댓글 작성자가 자신의 댓글을 삭제할 수 있는지 확인합니다.
- 기록 작성자가 자신의 공개 기록에 달린 댓글을 삭제할 수 있는지 확인합니다.
- 관계없는 다른 사용자는 삭제할 수 없는지 확인합니다.

### 9.4 댓글 답글

댓글에 답글을 다는 기능은 첫 버전에 포함하지 않습니다.

#### 확인 방법

- 댓글에 별도의 답글 작성 기능이 제공되지 않는지 확인합니다.

## 10. 좋아요

좋아요는 공개된 공부 기록과 공개된 오류 기록에서만 사용합니다. 공개된 할 일에는 좋아요를 제공하지 않습니다.

### 10.1 좋아요 누르기와 취소하기

#### 1) 사용자가 입력하거나 누르는 것

- 공개된 공부 기록 또는 오류 기록에서 좋아요를 누릅니다.
- 이미 좋아요를 누른 기록에서 다시 누르면 좋아요를 취소합니다.

#### 2) 정상 처리 결과

- 처음 누르면 해당 사용자와 기록의 좋아요가 저장됩니다.
- 한 사용자는 같은 기록에 좋아요를 한 번만 남길 수 있습니다.
- 다시 누르면 저장된 좋아요가 취소됩니다.
- 화면에서 내가 좋아요를 눌렀는지 알 수 있어야 합니다.
- 좋아요 전체 개수를 화면에 표시합니다.

#### 3) 잘못 입력하거나 실패한 경우

- 비공개 기록과 공개된 할 일에는 좋아요를 남길 수 없습니다.
- 처리에 실패하면 화면의 좋아요 상태를 실제 저장 상태와 다르게 보여주지 않고 실패 사실을 알려줍니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 로그인한 사용자는 공개된 공부 기록과 오류 기록에 좋아요를 누르거나 취소할 수 있습니다.
- 자신의 공개 기록에는 좋아요를 누를 수 없습니다.
- 좋아요 전체 개수만 표시하며 누가 눌렀는지는 보여주지 않습니다.

#### 5) 확인 방법

- 같은 사용자가 같은 기록에 좋아요를 중복해서 남길 수 없는지 확인합니다.
- 다시 누르면 좋아요가 취소되는지 확인합니다.
- 다른 공개 공부 기록과 오류 기록에는 각각 별도로 좋아요를 남길 수 있는지 확인합니다.
- 공개 할 일에는 좋아요 기능이 없는지 확인합니다.

## 11. 신고

### 11.1 공개 기록 신고

#### 1) 사용자가 입력하거나 누르는 것

- 공개 기록에서 신고 기능을 누릅니다.
- 신고 사유를 1~500자로 입력하고 신고 버튼을 누릅니다.

#### 2) 정상 처리 결과

- 신고 내용이 운영자가 확인할 수 있는 상태로 저장됩니다.
- 신고만으로 공개 기록을 자동 삭제하지 않습니다.
- 신고한 사용자에게 신고가 접수되었다는 안내를 보여줍니다.

#### 3) 잘못 입력하거나 실패한 경우

- 로그인하지 않은 사용자는 신고할 수 없습니다.
- 비공개 기록은 다른 사용자가 볼 수 없으므로 신고할 수 없습니다.
- 신고 처리에 실패하면 접수된 것처럼 표시하지 않고 실패 사실을 알려줍니다.
- 같은 사용자는 같은 기록을 한 번만 신고할 수 있습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 로그인한 사용자가 공개 기록을 신고할 수 있습니다.
- 저장된 신고 내용은 운영자가 확인할 수 있습니다.
- 기록 작성자에게는 신고 사실을 알리지 않습니다.

#### 5) 확인 방법

- 로그인한 사용자가 공개 기록을 신고할 수 있는지 확인합니다.
- 신고 뒤에도 기록이 자동으로 삭제되지 않는지 확인합니다.
- 운영자가 저장된 신고를 확인할 수 있는지 확인합니다.
- 로그인하지 않은 상태에서는 신고할 수 없는지 확인합니다.

### 11.2 댓글 신고

#### 1) 사용자가 입력하거나 누르는 것

- 공개 기록에 달린 댓글에서 신고 기능을 누릅니다.
- 신고 사유를 1~500자로 입력하고 신고 버튼을 누릅니다.

#### 2) 정상 처리 결과

- 신고 내용이 운영자가 확인할 수 있는 상태로 저장됩니다.
- 신고만으로 댓글을 자동 삭제하지 않습니다.

#### 3) 잘못 입력하거나 실패한 경우

- 로그인하지 않은 사용자는 신고할 수 없습니다.
- 신고 처리에 실패하면 접수된 것처럼 표시하지 않고 실패 사실을 알려줍니다.
- 같은 사용자는 같은 댓글을 한 번만 신고할 수 있습니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 로그인한 사용자가 댓글을 신고할 수 있습니다.
- 저장된 신고 내용은 운영자가 확인할 수 있습니다.
- 댓글 작성자에게는 신고 사실을 알리지 않습니다.

#### 5) 확인 방법

- 로그인한 사용자가 댓글을 신고할 수 있는지 확인합니다.
- 신고 뒤에도 댓글이 자동으로 삭제되지 않는지 확인합니다.
- 운영자가 저장된 신고를 확인할 수 있는지 확인합니다.

### 11.3 운영자의 신고 확인

#### 1) 사용자가 입력하거나 누르는 것

- 운영자는 운영자 전용 화면에서 신고 내용을 확인합니다.

#### 2) 정상 처리 결과

- 운영자는 저장된 공개 기록 신고와 댓글 신고를 확인할 수 있어야 합니다.
- 운영자는 신고 내용을 확인하고 문제가 있는 기록이나 댓글을 삭제할 수 있습니다.

#### 3) 잘못 입력하거나 실패한 경우

- 운영자가 아닌 사용자는 저장된 신고 내용을 볼 수 없어야 합니다.
- 신고 목록을 불러오지 못하면 실패 사실을 알려줘야 합니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 운영자만 저장된 신고 내용을 볼 수 있습니다.
- 서비스 관리자가 별도로 지정한 관리자 계정만 운영자로 인정합니다.

#### 5) 확인 방법

- 일반 사용자가 신고 내용을 볼 수 없는지 확인합니다.
- 운영자가 공개 기록 신고와 댓글 신고를 확인할 수 있는지 확인합니다.

## 12. 내 기록 홈 화면

### 12.1 홈 화면 이용

#### 1) 사용자가 입력하거나 누르는 것

- 로그인한 사용자가 내 기록 홈 화면을 엽니다.
- 공부 기록, 할 일, 오류 기록 중 원하는 메뉴를 누릅니다.
- 계정 설정에서 닉네임 변경 기능으로 이동할 수 있습니다.

#### 2) 정상 처리 결과

- 자신의 공부 기록, 할 일, 오류 기록으로 이동할 수 있습니다.
- 밝은 배경과 읽기 쉬운 카드 형태로 핵심 기록이 보입니다.
- 메뉴 이름과 위치를 분명하게 표시합니다.
- 홈에는 최근 공부 기록 3개, 남은 할 일 5개, 미해결 오류 3개를 보여줍니다.

#### 3) 잘못 입력하거나 실패한 경우

- 홈에 필요한 내용을 불러오지 못하면 잘못된 정보를 보여주지 않고 실패 사실을 알려줍니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 로그인한 사용자가 자신의 홈 화면을 볼 수 있습니다.
- 다른 사용자의 내 기록 홈 화면은 볼 수 없습니다.

#### 5) 확인 방법

- 홈에서 공부 기록, 할 일, 오류 기록 화면으로 이동할 수 있는지 확인합니다.
- 다른 사용자의 비공개 기록이 홈에 나타나지 않는지 확인합니다.
- 컴퓨터와 휴대폰에서 글과 메뉴를 읽고 누를 수 있는지 확인합니다.

## 13. 반응형 화면과 디자인

### 13.1 컴퓨터와 휴대폰에서 사용

#### 1) 사용자가 입력하거나 누르는 것

- 사용자는 컴퓨터 또는 휴대폰 브라우저에서 BuildLog를 엽니다.
- 같은 주요 기능을 각 화면 크기에서 사용합니다.

#### 2) 정상 처리 결과

- 화면 크기에 맞춰 내용이 읽기 쉽게 정리됩니다.
- 밝은 아이보리색 배경과 파란색 강조 색상을 사용합니다.
- 기기에 기본으로 설치된 읽기 쉬운 글꼴을 사용합니다.
- 카드 형태로 목록과 기록을 보여줍니다.
- 메뉴와 버튼은 처음 사용하는 사람도 이해하기 쉬운 이름을 사용합니다.
- 화려한 효과보다 기록 작성과 찾기에 집중합니다.

#### 3) 잘못 처리된 경우

- 글이 화면 밖으로 잘리거나 주요 버튼을 누를 수 없다면 정상 동작으로 보지 않습니다.
- 화면 크기가 달라졌을 때 기능이 사라지면 안 됩니다.

#### 4) 볼 수 있거나 관리할 수 있는 사람

- 로그인 여부와 기록 공개 범위에 따른 기존 권한 규칙을 그대로 따릅니다.

#### 5) 확인 방법

- 컴퓨터 크기와 휴대폰 크기에서 회원가입, 로그인, 기록 관리, 검색, 공개 기록 이용이 가능한지 확인합니다.
- 긴 제목과 긴 내용이 화면을 벗어나지 않고 읽을 수 있는지 확인합니다.

## 14. 첫 버전에 포함하지 않는 기능

다음 기능은 제공하지 않습니다.

- 이메일 확인
- 비밀번호 찾기
- 할 일 마감일
- 할 일 중요도
- 내 할 일 검색
- 댓글 답글

기능이 실수로 포함되지 않았는지 화면과 동작을 확인합니다.

## 15. 추가로 확정한 세부 규칙

PRD만으로 판단하기 어려웠던 내용은 사용자와 협의해 다음과 같이 확정했습니다.

1. 가입이 끝나면 자동으로 로그인하고 내 기록 홈으로 이동합니다.
2. 이메일 형식을 확인하며 같은 이메일의 중복 가입을 금지합니다.
3. 비밀번호는 8자 이상입니다.
4. 닉네임은 2~20자이며 한글, 영문, 숫자, 밑줄을 사용할 수 있습니다.
5. 다른 사용자에게는 닉네임만 보여주고 이메일은 공개하지 않습니다.
6. 로그인에 성공하면 내 기록 홈으로 이동합니다.
7. 공부 기록과 오류 기록을 저장하면 해당 기록의 상세 화면으로 이동합니다.
8. 할 일을 저장하면 할 일 목록 화면에 머뭅니다.
9. 기록이나 댓글을 삭제하기 전에 확인창을 보여줍니다.
10. 공부 기록과 오류 기록의 수정 날짜와 시간을 저장하고 상세 화면에 표시합니다.
11. 기록을 삭제하면 댓글과 좋아요도 삭제하지만 신고 내역은 유지합니다.
12. 공개 기록을 비공개로 바꾸면 댓글과 좋아요는 보관하되 작성자만 볼 수 있습니다.
13. 새 할 일은 미완료로 시작합니다.
14. 완료한 할 일은 다시 미완료로 바꿀 수 있으며 완료 날짜와 시간은 지웁니다.
15. 해결한 오류는 다시 미해결로 바꿀 수 있습니다. 해결 날짜와 시간은 지우고 해결 방법은 유지합니다.
16. 빈 검색어로 검색하면 현재 목록 전체를 보여줍니다.
17. 일부 글자가 일치해도 검색하며 영문 대소문자는 구분하지 않습니다.
18. 내 오류 기록은 오류 제목, 오류 내용, 해결 방법을 검색합니다.
19. 공개 공부 기록은 제목과 내용, 공개 할 일은 제목, 공개 오류 기록은 오류 제목·오류 내용·해결 방법을 검색합니다.
20. 댓글 작성 시간을 표시하고 수정된 댓글에는 `수정됨`을 표시합니다.
21. 좋아요 전체 개수는 표시하지만 누가 눌렀는지는 보여주지 않습니다.
22. 작성자는 자신의 공개 기록에 좋아요를 누를 수 없습니다.
23. 신고 사유는 1~500자로 입력합니다.
24. 같은 사용자는 같은 기록이나 댓글을 한 번만 신고할 수 있습니다.
25. 신고자에게만 접수 완료를 알리고 신고당한 사용자에게는 알리지 않습니다.
26. 운영자는 React로 만든 운영자 전용 화면에서 신고를 확인하고, FastAPI를 통해 문제가 있는 기록이나 댓글을 삭제할 수 있습니다.
27. 서비스 관리자가 별도로 지정한 관리자 계정만 운영자로 인정합니다.
28. 홈에는 최근 공부 기록 3개, 남은 할 일 5개, 미해결 오류 3개를 보여줍니다.
29. 공부 기록과 오류 기록은 목록, 작성, 상세 화면을 각각 분리합니다.
30. 할 일은 목록 화면에서 추가, 완료 체크, 수정, 삭제를 모두 처리합니다.
31. 밝은 아이보리색 배경, 파란색 강조 색상, 기기 기본 글꼴을 사용합니다.
32. Python·FastAPI·React와 데이터베이스 연결 도구의 정확한 버전은 개발 시작 시 서로 호환되는 안정 버전으로 정합니다.
33. 현재 MVP의 데이터는 프로젝트 내부 SQLite3에 저장합니다. Supabase 연결은 관련 수업 이후로 미룹니다.
34. 프론트엔드는 React, 백엔드는 FastAPI로 분리하며 두 영역은 API로 데이터를 주고받습니다.
35. 날짜와 시간은 한국 표준시(`Asia/Seoul`)를 기준으로 저장하고 표시합니다.

새 기능이 필요해지더라도 임의로 추가하지 않고 별도로 결정합니다.
